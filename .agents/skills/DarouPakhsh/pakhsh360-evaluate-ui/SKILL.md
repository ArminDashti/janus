# WebUI Evaluate Design In General

## When to use

- User wants a general UI/design review against the global standard
- Inputs: one or many URLs, routes, source files, lists, or globs
- Output: `./.webui-reviewer/<PAGE-NAME>-<PAGE-TYPE>.md` per target
- Visual canon: [reference.md](reference.md)
- Browser: Cursor built-in IDE browser (`cursor-ide-browser`) only — never the user’s personal browser or `plugin-browse-browser` local Chrome
- Exclusions: do not implement fixes unless asked; do not evaluate against a custom proposal (use [webui-evaluate-design-for-custom-request](../webui-evaluate-design-for-custom-request/SKILL.md)); not functional testing
- Related: [webui-evaluate-design-for-custom-request](../webui-evaluate-design-for-custom-request/SKILL.md), [pakhsh360-propose-designs](../pakhsh360-propose-designs/SKILL.md)

## Objective

1. Collect and normalize review targets
2. Inspect each rendered page against the built-in global UI standard
3. Classify findings as Problem or Optional and score 0–10
4. Write one report per target and summarize the batch

## Workflow

### Step 1: Collect targets

Accept URLs, routes, files, lists, folders, or globs. Deduplicate. Normalize each to `page_label`, `page_name`, `page_type`, `open_target`, `file_path`.

### Step 2: Load canon

Open this skill’s checklist (below) and [reference.md](reference.md). Sibling pages inform consistency only — they do not lower the global bar.

**Archetypes**

| Archetype | Expect |
|-----------|--------|
| Data entry + list | Entry section → search/filter → clear data table |
| Dense multi-filter | Purpose-colored filter sections; dense multi-column choices |
| Search / filters | Page context + filter card + primary search action |
| Other | Same bar for hierarchy, spacing, actions |

**Checklist (every fail is a finding)**

- Shell: clear page context; content on calm surfaces, not a flat dump
- Sections: clear header + body; consistent radius and vertical rhythm
- Forms: visible labels; consistent alignment; required markers; field width fits content
- Actions: primary vs secondary vs destructive distinct; groups sit with their content
- Tables: distinct header; usable width; clear row actions
- Typography / color: coherent font system; shared color roles
- A11y / defects: contrast and focus; no overflow/overlap; status not by color alone

**Browser:** Cursor built-in IDE browser (`cursor-ide-browser`) only. Source if URL unreachable. **Never** Playwright MCP, browser-use, Browserbase, the user’s personal browser, `plugin-browse-browser` local mode, or Windows MCP desktop tools for web pages.

### Step 3: Inspect each target

Isolated browser: navigate → snapshot → screenshot. Pick archetype. Walk the checklist. Record every fail with evidence. Continue the queue if one target fails to open.

### Step 4: Classify

| Bucket | Meaning |
|--------|---------|
| **Problem** | Breaks the global standard or clear usability |
| **Optional** | Mild polish / soft consistency |

### Step 5: Score (0–10)

| Score | Guide |
|-------|-------|
| 9–10 | No Problems; at most trivial Optionals |
| 7–8 | Few small Problems or several Optionals |
| 5–6 | Clear Problems in one or two major areas |
| 3–4 | Many Problems across structure/forms/actions |
| 0–2 | Largely ignores the global standard |

### Step 6: Write report

Path: `./.webui-reviewer/<PAGE-NAME>-<PAGE-TYPE>.md`

```markdown
This report was generated by <AGENT-NAME> at YYYY-MM-DD | HH:MM
File path: <path or URL>

Rate from 10: <0-10>
Number of Issue: <count of Problem items>
Number of optional: <count of Optional items>

Problem:
1. <title> — <where>. Standard expects <rule>. Why non-standard: <reason>. Evidence: <…>.

Optional:
1. …
```

Empty section → `None.`

### Step 7: Batch reply

```text
WebUI design evaluation complete:
- Requested: <n>
- Reviewed: <n>
- Skipped / failed: <list or none>
- Reports:
  - <label → ./.webui-reviewer/…> (rate/10, issues: n, optional: m)
```

## Safety rules

1. **Never** implement fixes unless asked.
2. **Never** invent findings without evidence.
3. **Never** score by stack or file type.
4. **Never** store secrets in reports.
5. **Always** explain why each item is non-standard.
6. **Always** finish the full multi-target queue.
7. **Always** use Cursor built-in IDE browser (`cursor-ide-browser`) only — never Playwright MCP, browser-use, Browserbase, the user’s working browser, `plugin-browse-browser` local mode, Windows MCP desktop tools for web pages, or OS default-browser open.
8. **Never** interrupt the user’s desktop browsing session.

## Examples

**Example 1:** Single live URL

- Input: `http://localhost:3010/Pages/Orders.aspx`
- Output: `./.webui-reviewer/Orders-html.md` with Problems, Optionals, and rate

**Example 2:** Batch of files

- Input: list of page paths
- Output: one report per reachable target; batch summary with skipped list
